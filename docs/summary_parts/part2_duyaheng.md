# 杜亚恒个人总结

## 1. 配置管理工作
我负责识别配置项（包括所有 `.md` 文档）、设计分支策略（main/dev/feature-*）并制定提交与合并规则。通过统一命名和 PR 审核流程，确保了版本的可追溯性和协作的规范性。

## 2. 冲突解决过程
在 `conflict.md` 中，我与马伯宁分别修改了同一行“当前结论”。我先合并自己的分支（无冲突），再合并对方分支时产生冲突。经协商，我们将结论改为“先经过 dev 分支集成测试，再由项目经理合并到 main”，手工解决后提交。

## 3. 个人收获与体会
本次实验让我真正掌握了 Git 分支策略和冲突解决技巧，不再是死记命令。作为配置管理员，我深刻体会到清晰的规则能减少很多协作矛盾，也为后续团队项目积累了宝贵经验。
